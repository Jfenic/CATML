## Reporting a Vulnerability

We take the security and integrity of CATML and its users seriously.

If you discover a security vulnerability or sensitive defect, **please do not disclose it publicly** via GitHub Issues or discussions. Instead, follow responsible disclosure:

1. **GitHub Security Advisory:** Submit a private vulnerability report via [GitHub Security Advisories](https://github.com/Jfenic/CATML/security/advisories/new).
2. **Direct Contact:** If GitHub Advisories is unavailable, contact the project maintainers directly via repository owner contact channels.

Please provide:
- A clear description of the vulnerability.
- Steps or a minimal proof-of-concept (PoC) to reproduce the issue.
- Potential impact and affected modules/components.

We acknowledge reports within 48 hours and coordinate a coordinated fix before publishing an advisory.

## Threat Model & Security Posture

CATML is architected as a **local-first, governed toolkit for machine learning**. It adheres to explicit security and privacy principles:

### 1. Data Privacy & Zero Telemetry
- **Local-First Execution:** By default, datasets, intermediate splits, models, logs, and artifacts remain 100% on the local host.
- **Zero Silent Telemetry:** CATML does not phone home, track usage, or transmit dataset rows or schema information across external networks.

### 2. Model Artifact Deserialization
> [!WARNING]
> Machine learning serialization formats using Python's `pickle` or `joblib` can execute arbitrary code upon deserialization.

- **Load Only from Trusted Sources:** Never load `.pkl` artifacts received from untrusted parties or downloaded over unverified channels.
- **Integrity vs. Authenticity:** Sidecar `.sha256` checksums generated by CATML guarantee **accidental file corruption detection** (integrity). They do **not** protect against malicious adversaries with disk access who can modify both the `.pkl` and `.sha256` files simultaneously without a hardware or PKI digital signature.

### 3. Agentic & MCP Governance ("Propose ≠ Accept")
- **Controlled Application Bus:** AI agents interacting via MCP (Model Context Protocol) or LangGraph orchestrators do not have unrestricted access to arbitrary host commands or arbitrary file execution.
- **Auditing & Policies:** Agent actions are dispatched through typed CQRS commands and recorded in a durable SQLite ledger. Long-running or resource-intensive tasks operate under budget leases with cooperative cancellation.
