# Security Policy — CATML

## Supported Versions

We release patches and security fixes for the current minor release line:

| Version | Supported          | Status                                 |
| ------- | ------------------ | -------------------------------------- |
| 0.9.x   | :white_check_mark: | Current active release line            |
| 0.8.x   | :white_check_mark: | Supported for maintenance and patches  |
| < 0.8.0 | :x:                | Deprecated (please upgrade to >= 0.8) |

## Reporting a Vulnerability

We take the security and integrity of CATML and its users seriously.

If you discover a security vulnerability or sensitive defect, **please do not disclose it publicly** via GitHub Issues or discussions. Instead, follow responsible disclosure:

1. **GitHub Security Advisory:** Submit a private vulnerability report via [GitHub Security Advisories](https://github.com/Jfenic/CATML/security/advisories/new).
2. **Direct Contact:** If GitHub Advisories is unavailable, contact the project maintainers directly via repository owner contact channels.

Please provide:
- A clear description of the vulnerability.
- Steps or a minimal proof-of-concept (PoC) to reproduce the issue.
- Potential impact and affected modules/components.

We acknowledge reports within 48 hours and coordinate a fix before publishing an advisory.

## Threat Model & Security Posture

CATML is architected as a **local-first, governed toolkit for machine learning**. Full architecture and deployment guidelines are available in [`docs/trusted-deployment.md`](docs/trusted-deployment.md).

### 1. Data Privacy & Zero Telemetry
- **Local-First Execution:** By default, datasets, intermediate splits, models, logs, and artifacts remain 100% on the local host.
- **Zero Silent Telemetry:** CATML does not phone home, track usage, or transmit dataset rows or schema information across external networks.
- **Workspace Confinement:** Filesystem operations and media previews strictly enforce root directory containment, preventing path traversal attacks.

### 2. Model Artifact Deserialization (`joblib` / `pickle`)
> [!WARNING]
> Machine learning serialization formats using Python's `pickle` or `joblib` can execute arbitrary code upon deserialization.

- **Never Load Untrusted Models:** Never load `.pkl` artifacts received from untrusted third parties or downloaded over unverified channels.
- **Integrity vs. Authenticity:** Sidecar `.sha256` checksums generated by CATML guarantee **accidental file corruption detection** (integrity). They do **not** protect against malicious adversaries with disk access who can modify both the `.pkl` and `.sha256` files simultaneously without a hardware or PKI digital signature.
- **Hardening Roadmap:** Support for optional cryptographic digital signatures (HMAC/PKI) and safe interchange formats (ONNX for inference-only pipelines) is scheduled for future minor releases.

### 3. Remote Network Hardening & Fail-Closed Posture
- **Loopback Default:** Both Workbench (`127.0.0.1:8080`) and MCP server (`127.0.0.1:8000`) bind exclusively to loopback interfaces by default.
- **Fail-Closed Remote Binding:** Binding to external network interfaces (`0.0.0.0` or non-loopback IP) strictly requires authentication. Any attempt to use `--insecure-no-auth` remotely without explicitly setting the environment variable `CATML_ALLOW_INSECURE=1` is rejected with `PermissionError`.
- **Fragment-Only URLs:** Access tokens are provided using client-side fragments (`/#token=...`), ensuring tokens are never transmitted across HTTP requests or leaked in server access logs.
- **Production Deployments:** When deployed on LAN or cloud VPS, CATML services must be placed behind an authenticated TLS reverse proxy (Nginx, Caddy, Envoy). See [`docs/trusted-deployment.md`](docs/trusted-deployment.md) for reference configurations.

### 4. Agentic & MCP Governance ("Propose ≠ Accept")
- **Controlled Application Bus:** AI agents interacting via MCP (Model Context Protocol) or LangGraph orchestrators do not have unrestricted access to arbitrary host commands or arbitrary file execution.
- **Compact Defaults:** Analysis tools operate in compact mode (`compact=True`) by default to prevent leaking raw dataset rows into LLM context windows.
- **Auditing & Policies:** Agent actions are dispatched through typed CQRS commands and recorded in a durable SQLite ledger. Long-running tasks operate under budget leases with cooperative cancellation.

### 5. Supply Chain & Dependencies
- Upstream dependencies are audited using `pip-audit` in CI workflows.
- Heavy optional extras (`torch`, `torchvision`, `optuna`) specify upper version bounds to mitigate unexpected upstream breakages.
- Release artifacts are published with SHA-256 integrity checksums.
